# Skill: bug-report

Этот навык формирует **воспроизводимый** баг-репорт. Воспроизводимость — главный критерий: если по твоим шагам нельзя повторить дефект, репорт бесполезен.

## Когда использовать

Используй этот навык всегда, когда нужно зафиксировать дефект в проекте DesignLint AI. Это включает:

- Жалобу от пользователя в свободной форме («не работает Fix»).
- Скриншот с явной аномалией (счётчик показывает не то, что ожидалось).
- Лог из `logs/runtime.log` с `error` или `warn`.
- Регрессию, найденную при прогоне тест-матрицы.
- Edge-case, проявившийся при ручной проверке (Cmd+Z после Fix, обрыв сети при `callGemini` и т.д.).

## Что НЕ делай этим скиллом

- Не предлагай **исправление**. Это работа `@lead-architect` (разведка) → `@backend` / `@ui-engineer` (правка). QA Inspector только фиксирует факт.
- Не ставь **severity** или приоритет. Оценку «блокер v1.0 vs не блокер» делает `@lead-architect` после получения репорта (с эскалацией к пользователю при необходимости).
- Не пиши репорт без воспроизведения — если нет шагов, как повторить, формат не работает.

## Обязательные поля

| Поле | Что туда писать |
|---|---|
| `BUG-N` | Сквозная нумерация в проекте. Если нет реестра — спроси `@release-scribe` или используй временный номер `BUG-?`. |
| Среда | ДС `S/M/L`, Scope `Selection/Page/All`, AI `on/off`, версия плагина (из `package.json` → `version`). |
| Шаги воспроизведения | Пронумерованный список действий **строго в том порядке**, в котором их повторит другой человек. Никаких «обычно», «иногда», «бывает». |
| Ожидалось | Что должно было произойти, согласно acceptance criteria или здравому смыслу. Если есть прямая ссылка на acceptance — приведи её. |
| Фактически | Что реально произошло. Никаких «вроде», «кажется» — только наблюдаемые факты. |
| Доп. данные | Скриншот, релевантные строки из `logs/runtime.log`, версия. |

## Опциональные поля

| Поле | Когда добавлять |
|---|---|
| Гипотеза причины | Если из контекста видна вероятная причина (например, симметрия `PluginMessage` нарушена). Краткая, без углубления. |
| Предлагаемая маршрутизация | `@lead-architect` → `@<исполнитель>`. По правилам из `CLAUDE.md`. |
| Регрессия из | Ссылка на acceptance criteria закрытой фазы (Ф.NN.X), которую этот баг нарушает. |

## Формат вывода

Используй ровно этот шаблон:

```markdown
## [BUG-N] <короткое название>

**Среда:** ДС <S/M/L>, Scope <Selection/Page/All>, AI <on/off>, plugin v<X.Y.Z>

**Шаги воспроизведения:**
1. <действие>
2. <действие>
3. <действие>

**Ожидалось:** <что должно было произойти>

**Фактически:** <что произошло>

**Доп. данные:**
- Скриншот: <ссылка/прикреплён>
- Console (`logs/runtime.log`):
  ```
  <релевантные строки>
  ```
- Версия: v<X.Y.Z>

**Гипотеза причины:** <если есть, кратко>

**Предлагаемая маршрутизация:** @lead-architect → @<исполнитель>

**Регрессия из:** Ф.<NN.X> (если применимо)
```

## Примеры

### Хороший баг-репорт

```markdown
## [BUG-12] Чекбокс категории не фильтрует Review

**Среда:** ДС M, Scope Page, AI off, plugin v0.14.13

**Шаги воспроизведения:**
1. Открыть Figma desktop, тестовый файл `dl-test-medium.fig`.
2. Выделить страницу `Components`.
3. Запустить scan через кнопку `Scan`.
4. Дождаться окончания (Spinner исчезает, открывается Dashboard).
5. Снять чекбокс `Colors`.
6. Перейти на экран `Review` через кнопку `Fix violations`.

**Ожидалось:** счётчик на Dashboard уменьшился, на экране Review показаны только нарушения категории Typography.

**Фактически:** счётчик уменьшился (с 47 до 18), но в Review всё ещё отображаются нарушения категории Colors (12 штук вперемешку с Typography).

**Доп. данные:**
- Скриншот: см. вложение `bug-12-review.png`.
- Console: чисто, ошибок нет.
- Версия: v0.14.13

**Гипотеза причины:** `selectedCategories` сбрасывается при переходе Dashboard → Review, либо `filteredViolations` в ReviewFix не учитывает фильтр.

**Предлагаемая маршрутизация:** @lead-architect → @ui-engineer

**Регрессия из:** Ф.13.5 (acceptance: «снятие чекбокса категории фильтрует Review»)
```

### Плохой баг-репорт (что НЕ делать)

```markdown
Чекбоксы вроде не работают в Review. Нужно посмотреть, кажется фильтр сломался.
Скриншот приложу.
```

Что не так:
- Нет шагов воспроизведения — другой человек не повторит.
- «Вроде», «кажется» — гадательные формулировки вместо фактов.
- Нет среды — на каком ДС, какой Scope, какая версия.
- Нет разделения «ожидалось» / «фактически».
- Нет console-данных или явного указания «console чисто».

## Перед отдачей репорта проверь

- [ ] Все обязательные поля заполнены.
- [ ] Шаги пронумерованы и однозначны (никаких «обычно», «иногда», «бывает»).
- [ ] «Ожидалось» и «Фактически» — наблюдаемые факты, не интерпретация.
- [ ] Среда указана полностью (ДС, Scope, AI, версия).
- [ ] Доп. данные приложены или явно сказано «console чисто».
- [ ] Если предлагается маршрутизация — она соответствует правилам из `CLAUDE.md`.
- [ ] Severity и приоритет НЕ выставлены — это решение `@lead-architect`.
