Запрос пользователя: $ARGUMENTS (опционально — номер сессии)

Делегируй `@release-scribe` закрытие сессии. Обязательное поведение:

1. Прочитать `.claude/skills/session-report/SKILL.md`.
2. Прочитать 2–3 последних отчёта в `context/sessions/` для стилистики.
3. Собрать раздел «Коммиты сессии» из своего `git log` с реальными хешами и версиями (это та же роль — никаких внешних запросов делать не нужно).
4. Запросить у `@qa` обновления раздела «Известные ограничения».
5. Сформировать отчёт строго по шаблону: Контекст / Выполненные шаги / Архитектурные решения / Известные ограничения / Решения по объёму / Коммиты сессии / Открытые вопросы.
6. Сверить новые термины с глоссарием (`context/glossary/Glossary.md`). Если появились — добавить с маркером 🟡.
7. Если в сессии было утверждённое архитектурное решение от Product Owner с вариантами от `@lead-architect` — предложить написать ADR (но не писать без явного согласия).
8. Сохранить отчёт в `context/sessions/session-report-NN.md`.

Перед отдачей — пройти по чеклисту в конце SKILL.md.
