## Цель

Привести 9 ДС-компонентов в `src/ui/components/ui/` к визуалу макетов 2026-05-07: добавить `BackButton.tsx`, расширить `Header.tsx` контекстной иконкой (`gear` / `home` / `none`), не затрагивая продуктовые экраны.

## Зачем

Ф.16.1 закрыла токены — следующий слой редизайна это компоненты ДС, которые потребляются всеми 11 экранами. Без выровненных компонентов фазы экранов (Ф.16.3–Ф.16.6) не могут стартовать корректно: каждая правка экрана сейчас бы упиралась в «сначала поправить кнопку/чип/чекбокс/Header». Ф.16.2 фиксирует визуал примитивов один раз, прежде чем экраны начнут их потреблять. После PO-ответа на #11(a) (2026-05-08) Header вошёл в этот шаг как 9-й компонент: расширение API делается сейчас, подключение к экранам — в Ф.16.3+.

## Действие

`@ui-engineer` правит `src/ui/components/ui/`:

1. **Стилевые правки** (сверка hover/active/disabled с эталонами `02-ready-to-scan.png`, `04-reportview-closed.png`, `09-settings-1.png`): `Button.tsx`, `Checkbox.tsx`, `IconButton.tsx`, `SelectField.tsx`, `Input.tsx`. API не меняется. Tokens — те, что в `tokens.ts` после Ф.16.1 (`tagContent #FFFFFF`, `typography.body 16/20`, `containerPadding: 26`).

2. **Расширение `Tag.tsx`:** добавить prop `active?: boolean` (default `true`) для поддержки selectable-варианта (соответствие JSON ДС `Tags`: variants `Tag_Active` / `Tag_Disable`). Существующий `onRemove` API сохраняется — единственный текущий потребитель в `App.tsx` не ломается. Стилевая часть: Active = тёмный фон + светлый текст (как сейчас), Disable = светлый фон + outline + тёмный текст.

3. **Новый компонент `BackButton.tsx`:** обёртка `<button>` (не `<div onClick>`), синяя стрелка `<` + текст «Back», проп `onClick: () => void`, импортируется из `src/ui/components/ui/`. Соответствует JSON-компоненту `Lable_icons`. Не подключается к экранам в этом шаге — потребители (`ReviewFix.tsx`, `Settings.tsx`) переедут на него в Ф.16.5/Ф.16.6.

4. **Spinner.tsx:** оставить как есть. Variant `Stop` из JSON ДС не используется ни одним текущим экраном — scope-cap.

5. **SelectField/Input** — см. блок 1 (стилевая правка), API без изменений.

6. **Расширение `Header.tsx`:**
   - prop `icon?: 'gear' | 'home' | 'none'`, **default `'none'`**. Безопасный default: существующие потребители без явного указания (`ScanDesignSystem.tsx`, `Settings.tsx`, `App.tsx` Ready-to-scan/done и т.д.) не получат неожиданную иконку до их явной миграции в Ф.16.3+.
   - prop `onIconClick?: () => void` — callback на клик по иконке. Если `icon !== 'none'` и `onIconClick` не передан — иконка отображается, но клик no-op (тихий fallback, без runtime-ошибки).
   - SVG для `'gear'` — текущая шестерёнка из `Header.tsx:9-14` (сохраняется без изменений; перенести в условный рендер).
   - SVG для `'home'` — новый: извлечь из `Component 1` variant `Home` в JSON ДС (`context/design/design-system-2026-05-07.json`), либо нарисовать inline SVG по эталону скриншота `02-ready-to-scan.png` (24×24, line-style под текущий gear). Стиль кнопки-обёртки идентичен gear-варианту.
   - **Header в этом шаге не подключается к экранам.** Потребители на Home, Ready-to-scan, ReviewFix card, Done переедут на новый API в Ф.16.3+. Сейчас — только сам компонент с расширенным API.

7. **`tsc --noEmit`** прогон после каждого блока правок (минимум 4: после стилевых, после Tag API, после BackButton, после Header). После завершения всех правок — `npm run build`, замер `dist/ui.js` Δ.

## Критерий успеха

- `npm run build` проходит.
- Δ `dist/ui.js` ≤ +4 KB (BackButton ~1KB + расширение Tag ~0.5KB + расширение Header (новый SVG home + condition) ~0.5–1KB + стилевые правки нейтрально).
- `@qa` визуально сверяет ДС-компоненты на всех 11 эталонах макета: Button hover/active/disabled на экранах 02/04/06/09, Tag selectable Active/Disable на 02 (через Storybook-screenshot или прямой просмотр на собранном плагине Product Owner'ом), Checkbox/Input на 09, SelectField close/open на 04/05, BackButton как изолированный компонент, Header в трёх вариантах (`gear` / `home` / `none`) как изолированный компонент.

## Решения по объёму (защита от scope creep)

### Что входит в Ф.16.2 (9 компонентов)

| Компонент | Тип правки | Вес |
|---|---|---|
| `Button.tsx` | стилевая | S |
| `Tag.tsx` | расширение API (`active?: boolean`) + стилевая | S-M |
| `Checkbox.tsx` | стилевая | S |
| `IconButton.tsx` | стилевая | S |
| `SelectField.tsx` | стилевая (chevron Down/Up + open/closed) | S |
| `Input.tsx` | стилевая | S |
| `Spinner.tsx` | без правки (явный scope-cap) | — |
| `BackButton.tsx` | **новый файл** | S |
| `Header.tsx` | расширение API (`icon` + `onIconClick`) + новый SVG `home` | S-M |

### Зависимости для Ф.16.3+

🔴 **`handleNavigateHome` (без сброса state)** — реализуется при подключении Header в Ф.16.3, **не в Ф.16.2**. Семантика клика по `home`: навигация на Home **БЕЗ сброса state.** Scope-выбор живёт. Результаты сканирования живут. AI explanation cache (`explanationsRef`) живёт. То есть `home`-клик ≠ `handleReset()` (который ВСЁ сбрасывает). Это **новый путь** в навигационной модели — `setCurrentView('scanner')` без обнуления `detection` / `scopeChoice` / `explanationsRef.current`. Не переиспользовать `handleReset`. Зафиксировано в impact map, раздел C, вопрос #11(a). Решение PO от 2026-05-08.

### Что НЕ входит в Ф.16.2

- **Подключение Header с новым API к экранам** — Ф.16.3+ (Home → `icon='gear'`, Ready-to-scan / ReviewFix card / Done → `icon='home'` + `onIconClick={handleNavigateHome}`, Settings → `icon='none'`).
- **`handleNavigateHome` в `App.tsx`** — Ф.16.3 (зависимость, см. выше).
- **`ScopeSelector.tsx`** — экран, Ф.16.3 (включая возможное расширение до 5 чипов по #11b).
- **`Pagination`, `DashedPreviewBox`** — inline в ReviewFix.tsx (Ф.16.5).
- **`ReviewFixOverview`** — Ф.16.4 (выделение из App.tsx).
- **`Switch`, `Radio`, отдельный `Chevron`, `Loader Stop`, `Component 1` standalone, `ListRadio`** — JSON ДС содержит, но текущие экраны не используют. Не добавляем «на вырост».
- **Локализация** — UI остаётся English-only (зафиксировано Product Owner в impact map).

## Тесты под риском

- 🟢 **Юнит-тесты отсутствуют** в репозитории (`src/__tests__/` нет). Этот контур не ломается.
- 🟡 **Регрессии acceptance closed-фаз** (Ф.11.7.4 кэш Preview, ec830d3 fixedCount, 3cdf323 selectedCategories) — `@qa` проверяет по матрице.
- 🟡 **Визуальная регрессия Tag** — Tag с прежним API `onRemove` не должен сломаться при добавлении `active`. Default `active=true` сохраняет старое поведение.
- 🟡 **Визуальная регрессия Header** — все текущие потребители Header вызывают компонент без явного `icon`-prop. Default `icon='none'` означает: иконка не рендерится. Это **меняет** текущий визуал на Home (где сейчас gear показан безусловно). Корректное поведение: до Ф.16.3 ScanDesignSystem либо вручную передаёт `icon='gear'` уже сейчас (рекомендую), либо временно теряет иконку на 1 фазу. **Решение `@ui-engineer` в момент реализации** — рекомендую добавить `icon='gear'` в `<Header>` внутри `ScanDesignSystem.tsx` сразу при правке `Header.tsx`, чтобы не было визуальной регрессии Home между Ф.16.2 и Ф.16.3. Это единственный точечный коннект к экрану в этом шаге, оправдан тем, что без него Home теряет иконку.

## Открытые вопросы перед стартом

- 🔴 **Зависимость для Ф.16.3:** `handleNavigateHome` (без сброса state) реализуется при подключении Header `icon='home'` к экранам в Ф.16.3, не в Ф.16.2. Не забыть при формулировке шага Ф.16.3, чтобы `@ui-engineer` не использовал `handleReset` по ошибке.
- 🟡 **Точечный коннект Header → ScanDesignSystem:** см. блок «Тесты под риском» выше — `@ui-engineer` в момент правки решает, передаёт ли `icon='gear'` в Home сразу (рекомендуется) или оставляет default `'none'` до Ф.16.3.
