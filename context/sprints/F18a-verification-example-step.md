### Новые риски, замеченные при сборке

**Риск-A: Ф.18a допускает COMPONENT-таб, но R6 не закрыта.** В шаге 18.6 таб Component присутствует, в шаге 18.3 (parser) нет жёсткой проверки published. Если PO выберет неопубликованный компонент эталоном, parser отработает «как будто всё ок», но без teamLibrary матчинг по library-варам потеряет имена. **Mitigation в Ф.18a:** в parser добавляется fallback — для unpublished components используем имена локальных variables (если есть). Жёсткая проверка отложена до R6 в Ф.18b. Это явно отражено в шаге 18.3.

**Риск-B: При R7 (один глобальный эталон в `clientStorage`) кнопка «Добавить пример» в макете E3 в Ф.18a физически перезаписывает существующий.** Ф.18a включает шаг 18.6, но **не** 18.6.5 (Tabs-компонент). В шаге 18.6 кнопка «Add another example» отображается **disabled с тултипом «Replaces current example»** — чтобы не сломать ментальную модель PO раньше, чем будет проверена сама гипотеза эталона. UX-решение «overwrite vs disabled» — **выбираем сами как `@lead-architect`**: disabled-with-tooltip. Триггер эскалации не сработал (не меняет публичный контракт, не требует нового цвета).

## 2. Концепция Ф.18a в одном абзаце

Проверяем гипотезу: помогает ли эталон в кадре решить проблему подбора токенов. Юзер выбирает на холсте эталон (фрейм/секцию/компонент/layout), плагин парсит из него palette токенов и при сканировании выделения предлагает кандидатов **только из этой palette**, а не из полной библиотеки. AI-prompt при этом получает контекст «в эталоне этот слот использует токен X». Темизация Light/Dark, bulk-undo, удаление старого флоу и санитарная зачистка — **отложены в Ф.18b/c**. Цель Ф.18a — собрать alpha-билд v0.18.0-alpha и дать PO визуально сравнить с Ф.17.

## 3. Точка проверки концепции (что PO смотрит после Ф.18a)

PO запускает alpha-билд v0.18.0-alpha в Figma desktop и проходит **три сценария**, сравнивая с поведением v0.17 (текущий main):

### Сценарий-1: «Эталон Button → скан карточки с похожим синим»

- Эталон: компонент Button (фон Brand/Primary, синий).
- Скан: фрейм-карточка с hardcoded синим (близок и к Brand/Primary, и к Blue/9 из общей палитры).
- **Ожидаемое отличие от Ф.17:** в Ф.17 в SelectField на первом месте по hex-расстоянию мог быть Blue/9. В Ф.18a первым кандидатом обязан быть Brand/Primary (он в эталоне), даже если Blue/9 формально ближе по hex. Если этого нет — гипотеза не подтвердилась.
- **Что наблюдает:** SelectField в ReportView, секция «From example», порядок токенов.

### Сценарий-2: «Эталон Card → AI-объяснение знает имя эталона»

- Эталон: компонент Card.
- Скан: фрейм с нарушением fill.
- **Ожидаемое отличие от Ф.17:** в AI-объяснении должен фигурировать контекст эталона («In example «Card» this slot uses ...»). В Ф.17 AI получал список из 20 имён без иерархии «эталон / прочие».
- **Что наблюдает:** текст AI suggestion, наличие имени эталона в формулировке.

### Сценарий-3: «Эталон сохраняется между запусками плагина»

- Выбрать эталон, закрыть плагин, открыть снова.
- **Ожидаемое поведение:** чип `Example: <имя> ✕` сразу виден в Header, повторно парсить не надо. Если узел эталона удалён в Figma — чипа нет, всё в исходном состоянии.
- **Что наблюдает:** Header после reopen, поведение при удалённом узле.

### Решение PO после трёх сценариев

- **Сценарии 1+2 показали отличие в правильную сторону → продолжаем в Ф.18b** (темизация R4, удаление search/library hint R5, bulk-undo R1).
- **Сценарии 1+2 не показали отличия или показали хуже → останавливаемся**, идём в ретроспективу, переопределяем гипотезу. Ф.18b не запускается.
- **Сценарий 3 сломан** — это не блокер концепции, но обязательный фикс перед Ф.18b.

### Шаг 18.3 — Создать `src/sandbox/exampleParser.ts` (парсинг эталона)

**Цель:** Sandbox-функция `parseExample(scope: ExampleScope): Promise<Example>` — рекурсивно обходит выбранный узел, собирает все слоты с привязанными токенами (color/typography/spacing/radius) и возвращает `Example`.

**Зачем:** Это ядро новой логики «эталон в кадре». Без этой функции концепция не существует физически — нечего проверять в Ф.18a.

**Действие:** `@backend`: создать новый файл `src/sandbox/exampleParser.ts`. Внутри:
- Получить узел-эталон через `figma.currentPage.selection[0]` (валидация: ровно один selected, тип SceneNode).
- Рекурсивно (по образцу `walkNode` в `scanner.ts`) собрать `boundVariableId` (для color), `fillStyleId`, `textStyleId`, `fontSize`, autolayout-spacing, cornerRadius.
- Для каждого слота — резолв в `tokenName` через `getVariableByIdAsync` / `getStyleByIdAsync`.
- Для color-слотов с varId записать **`hexInExampleTheme = currentValue`** (в Ф.18a берётся первый mode через `Object.values(valuesByMode)[0]`, как в текущем `designSystemParser.ts:255`). Это упрощение для Ф.18a — полноценный `resolveForConsumer(node)` появится в Ф.18b (R4).
- Сохранить `node.resolvedVariableModes` в `Example.resolvedVariableModes` (даже не используя в Ф.18a — пригодится в Ф.18b).
- Для unpublished components не делать жёсткой проверки — парсить как обычный узел (по решению из 18.0).
- Вернуть `Example { exampleNodeId, examplePageId, name, scope, slots, resolvedVariableModes, createdAt }`.

**Критерий успеха:** Файл создан, экспортирует `parseExample`. Сборка `dist/code.js` Δ ≤ +5 KB. Юнит-тестов нет (нет рантайма Figma). Ручная проверка: PO выбирает «Button» в Figma, в логе sandbox появляется структура `Example` с 3+ slots.

**Среда:** Claude Code в терминале + Figma desktop (для ручной проверки PO).

**Исполнитель:** @backend → @qa.

**Размер:** M.

**Acceptance «Готово, когда…»:** `parseExample` возвращает `Example` для тестового компонента. Есть ручная проверка PO с логом структуры. `tsc --noEmit` чисто.

**Зависимости:** 18.2.

**Риски:**
- R6 не закрыта окончательно (только отложена) → unpublished components парсятся «как обычные», имена library-вар могут быть `null`. Mitigation: в `parseExample` для случая `tokenName === null` подставлять fallback `"Unnamed token (#${hex})"` и логировать warning.
- Глубокая рекурсия на больших фреймах → время. Mitigation: лимит глубины 10 уровней (как в scanner.ts).

### Шаг 18.5 — Persist эталона в `clientStorage` (handlers `clear-example`, `get-example`)

**Цель:** Сохранять выбранный эталон в `figma.clientStorage` под ключом `'example-current'` и загружать его при старте плагина. Один глобальный эталон на файл (R7).

**Зачем:** PO ожидает, что чип «Example: <имя> ✕» остаётся после reopen плагина (как `selectedSource`). Это часть сценария-3 в точке проверки концепции (раздел 3).

**Действие:** `@backend`: расширить handler `parse-example` после успешного парсинга — `await figma.clientStorage.setAsync('example-current', JSON.stringify(example))`. Добавить handler `clear-example` — `await figma.clientStorage.deleteAsync('example-current')` + `figma.ui.postMessage({ type: 'example-loaded', data: { example: null } })`. Добавить handler `get-example` — load + проверка `figma.getNodeByIdAsync(example.exampleNodeId)` (если null — отдаём `example: null` и удаляем stale ключ). Симметрия catch обязательна для всех трёх handlers.

**Критерий успеха:** clientStorage работает: ключ `example-current` появляется при выборе эталона, исчезает при clear или при удалении узла-эталона. После reopen плагина handler `get-example` отдаёт сохранённый эталон. Ручная проверка PO в Figma desktop — чип Example остаётся после reopen.

**Среда:** Claude Code в терминале + Figma desktop.

**Исполнитель:** @backend → @qa.

**Размер:** S.

**Acceptance «Готово, когда…»:** Сценарий-3 из раздела 3 проходит: эталон сохраняется/восстанавливается между запусками; stale (удалённый) узел корректно сбрасывается в null.

**Зависимости:** 18.4.

**Риски:** Stale example при удалении узла-эталона. Mitigation: явная проверка через `getNodeByIdAsync` в handler `get-example` — закрывает риск.

### Шаг 18.7 — Новый state `currentView='example'` в `App.tsx`

**Цель:** Добавить новый view-state `'example'` в `App.tsx`, маршрут от Home → example → scanner.

**Зачем:** Переход между экранами должен быть детерминирован. Без этого VerificationExample не доступен пользователю.

**Действие:** `@ui-engineer`: в `src/ui/App.tsx` расширить тип `View` значением `'example'`. Новая ветка early-return: `if (currentView === 'example') return <VerificationExample ... />`. Переход Home → example: `handleMode0Complete` → `setCurrentView('example')` вместо `'scanner'`. Переход example → scanner: новый handler `handleExampleConfirmed` — `setCurrentView('scanner')`. **Старая ветка `currentView='scanner', status='idle'` (ReadyToScan) пока остаётся** — её удаление в Ф.18a не делаем (это часть Ф.18c-зачистки). **Критерий успеха:** Навигация Home → example → scanner работает в Figma desktop. Скриншот трёх экранов приложен. `tsc --noEmit` чисто.

**Среда:** Claude Code в терминале + Figma desktop.

**Исполнитель:** @ui-engineer → @qa.

**Размер:** S.

**Acceptance «Готово, когда…»:** Маршрут Home → example → scanner работает, ReadyToScan остаётся (в Ф.18a) недостижимым кодом — не удалён.

**Зависимости:** 18.6.

**Риски:** ReadyToScan превращается в dead code → растёт `dist/ui.js`. Mitigation: в Ф.18a допустимо (это alpha, не релиз), удаление в Ф.18b/c.

### Шаг 18.10 — `start-scan` в sandbox использует example вместо tokenSource/tokenPolicy (минимальная версия)

**Цель:** Handler `start-scan` в `code.ts` после загрузки snapshot загружает example из `clientStorage` и передаёт его в детектор. Детектор в Ф.18a использует `example.slots` как **дополнительный источник кандидатов** (без полной замены логики).

**Зачем:** UI больше не управляет tokenSource/tokenPolicy в новом флоу. Детектор должен видеть эталон. Без этого сценарий-1 не работает (пользователь не увидит, что Brand/Primary первым в SelectField).

**Действие:** `@backend`: в `src/sandbox/code.ts` handler `start-scan` — после `loadSnapshot()` вызвать `loadExample()` (читает `'example-current'` из clientStorage). Если example=null → ведём себя как Ф.17 (fallback на полную палитру). Если example задан — передаём его в детектор. **Минимальная правка детектора в Ф.18a:** в `pickTopCandidates` (`detector.ts:40-57`) перед существующей логикой добавить **boost для слотов из example**: если кандидат принадлежит `example.slots` — поднимаем его в начало списка. Полноценный `runDetectionWithExample` (шаг 18.9 общего плана) **в Ф.18a не делается** — это перенесено в Ф.18b. В каждое нарушение, где есть match со слотом эталона, проставляется `Violation.exampleSlot`.

**Критерий успеха:** Сценарий-1 проходит: при эталоне Button (с Brand/Primary) скан карточки с близким синим возвращает Brand/Primary первым кандидатом, Blue/9 — после. Без эталона поведение Ф.17 не сломано (регрессия baseline-acceptance Ф.17). `tsc --noEmit` чисто. Размер `dist/code.js` Δ ≤ +3 KB.

**Среда:** Claude Code в терминале + Figma desktop (PO для проверки).

**Исполнитель:** @backend → @qa (тест сценария-1 + регрессия Ф.17).

**Размер:** S (минимальная версия — boost в pickTopCandidates, не полная замена).

**Acceptance «Готово, когда…»:** Сценарий-1 проходит. Регрессия baseline Ф.17 (без эталона) не нарушена. `Violation.exampleSlot` проставлен в нарушениях, попавших в эталон.

**Зависимости:** 18.5 (load example из clientStorage), 18.8 (UI готов показать результат).

**Риски:** Минимальный boost вместо полной замены может оказаться недостаточным для сценария-1 (Brand/Primary всё-таки не первый). Mitigation: тестирование `@qa` с реальным компонентом до закрытия шага. Если boost недостаточен — переходим к полной `runDetectionWithExample` уже в Ф.18a (увеличение объёма шага до M).
