## Цель

Привести `Done.tsx` (финальный экран после Fix all) и `Settings.tsx` (экран настроек AI) в соответствие с эталонами 06 и 09/10/11 соответственно. В `Done.tsx` синхронизовать container padding с Ф.16.1 и прижать кнопки к низу окна. В `Settings.tsx` подключить ДС-компонент `BackButton` вместо inline `<div onClick>`, превратить три кнопки управления ключом (Save / Test / Remove) из conditional render в conditional disabled, чтобы реализовать три состояния экрана (`ai-off` / `entered` / `saved`) как derived state из существующих хуков.

## Зачем

`Done` и `Settings` — два последних экрана плагина без визуала макета 2026-05-07. Без них v1.0-submission невозможен: финальный пользовательский цикл (Home → Scan → Dashboard → Review → Fix → **Done** → **Settings**) визуально разрывается на двух экранах из семи. В Settings пользователь сейчас видит inline-текст «← Back» вместо синей `BackButton` с шевроном (recap из эталонов 09/10/11), и три кнопки управления ключом появляются/исчезают динамически (`{hasExisting && ...}`), что расходится с эталонами, где все три кнопки видны всегда и управляются через disabled. Параллельно Done использует `padding: spacing.s400` вместо `containerPadding: 26`, унаследованного от Ф.16.1 — это нарушает консистентность отступов между экранами.

## Действие

### 1. `src/ui/components/Done.tsx` — три точечные правки

- **Container padding**: `styles.root.padding: spacing.s400` → `spacing.containerPadding` (синхрон с Ф.16.1, остальные экраны).

Точная форма CSS — на усмотрение `@ui-engineer` (можно через `flex: 1` на спейсере, можно через `marginTop: auto`), важно соответствие эталону.

### 2. `src/ui/components/Settings.tsx` — три блока правок

#### 2a. BackButton подключение

#### 2b. Conditional render → conditional disabled (три состояния)

Удалить conditional render блока кнопок Test+Remove (строки 135-152 — `{hasExisting && (<div>...)</div>)}`). Развернуть в плоскую структуру **всегда видимых** трёх кнопок (Save / Test / Remove) с правилами disabled:

- `Save.disabled = !aiEnabled || key.trim().length === 0`
- `Test.disabled = !aiEnabled || !hasExisting || testing`
- `Remove.disabled = !aiEnabled || !hasExisting`
- `Input.disabled = !aiEnabled`

Block result-text от `handleTestKey` (строки 140-147) — **сохранить** между Test и Remove, рендерить условно: `{testResult && <div>...</div>}`. Тестовый результат не относится к состояниям, это отдельный feedback.

Layout трёх кнопок: вертикальный flex-column с `gap: spacing.s200`, как на эталонах. `marginTop: spacing.s300` от Input до Save (визуальная группа «ключ + действия»).

## Архитектурное решение по Settings

**Развилка PO (переопределена 2026-05-08):** Settings 1/2/4 — **не выбор канонического**, а ТРИ СОСТОЯНИЯ ОДНОГО ЭКРАНА.

**Решение @lead-architect:** Вариант B (Derived state) — состояния выводятся из существующих хуков `aiEnabled` (строка 24 Settings.tsx), `key` (строка 19), `hasExisting` (строка 21). Без `useReducer`, без новых state-хранилищ, без проброса props из App.tsx.

**Обоснование:**
1. Архитектурный принцип проекта: «Derived state вместо useState + useEffect» (CLAUDE.md раздел 5).
2. Все три флага уже есть в Settings.tsx — не вводим ничего нового.
3. State-machine через `useReducer` — overengineering для трёх флагов и пяти правил disabled.
4. Props через App.tsx нарушает инкапсуляцию (apiKey/hasExisting живут в Settings).

**Правила disabled** (контракт между состояниями и кнопками):

| Состояние | Условие | Save.disabled | Test.disabled | Remove.disabled | Input.disabled |
|---|---|---|---|---|---|
| `ai-off` (эталон 09) | `!aiEnabled` | true | true | true | true |
| `entered` (эталон 10) | `aiEnabled && !hasExisting` | `key.trim().length === 0` | true | true | false |
| `saved` (эталон 11) | `aiEnabled && hasExisting` | `key.trim().length === 0` | `testing` | false | false |

🟡 **Микро-неоднозначность Save на эталоне 11:** на эталоне Save показан disabled, но в Input стоит «A» (одна буква). По текущему правилу `Save.disabled iff key empty` — Save должен быть active при «A». Защитная интерпретация: оставляем текущее правило, считаем «A» в эталоне визуальной декорацией каретки. Если PO трактует иначе — фикс однострочный.
