# Ф.16.6.5 — Library variables scanning (Single-select модель)

> **Сформулировано:** lead-architect, 2026-05-09 (переписано с multi-select на single-select после решения PO).
> **По skill:** `.claude/skills/step-format/SKILL.md`
> **Зависимости:** Ф.16.6 закрыта (Settings + Done готовы — Settings в этой фазе НЕ трогается).
> **Блокирует:** Ф.16.7 (чистка + регрессия) — Ф.16.7 не стартует до закрытия Ф.16.6.5.
> **Решение PO 2026-05-09 (single-select):**
> - Multi-select модель источников **отклонена.**
> - На Home — 2 radio «Connected library» (с dropdown библиотек) / «Local library».
> - За один скан используется **один** источник: либо одна выбранная библиотека, либо локальные. Агрегирования нет.
> - Settings раздел «Token sources» **не создаётся.**
> - Capability `teamLibrary` в `manifest.json` — добавляем явно (ради будущей совместимости).

## Архитектурное ограничение, признанное PO

Library paint/text styles listing невозможен в текущем Plugin API. См. `context/architecture/impact-maps/2026-05-07-redesign-v1x.md` раздел F-pre.1. В Ф.16.6.5 поддерживаем **только library variables**, library styles остаются пассивно обнаруживаемыми через `BaseStyle.remote === true` при walking файла (как сейчас). Single-select модель — F-pre.4.

## Трек A — Sandbox/Shared (`@backend`)

### Шаг 16.6.5.A — Подключить library variables к скану ДС (single-select)

**Цель:** Расширить `discoverSources()` и `buildSnapshot()` поддержкой одиночно выбранной библиотеки или локальных источников через `figma.teamLibrary.*`, с batch-импортом, прогрессом и устойчивостью к permission errors.

**Зачем:** Сегодня `designSystemParser.ts` читает только локальные variables и styles. На реальных ДС клиентов токены живут в подключённых библиотеках (например, AltaIDE), и плагин их не видит — сканирование даёт ложно-завышенный список нарушений и пустой `Violation.candidates`. Без library variables submission v1.0 даст плохие отзывы. Single-select упрощает архитектуру: за один скан импортируется одна библиотека, не сумма по всем — снимается основной перформанс-риск multi-select модели и не требуется Settings UI для управления коллекциями.

**Действие:**
- `@backend`: правка `manifest.json` — добавить capability `teamLibrary` (если требуется в Figma 2026 — сверить с docs.figma.com на дату 2026-05-09; добавление безопасно для старых версий).
- `@backend`: расширить `src/sandbox/designSystemParser.ts`:
  - `discoverSources()` — возвращает структуру `{ libraries: { key, name, tokenCount }[], hasLocalStyles: boolean, hasLocalVariables: boolean }`. Каждая запись `libraries[]` — одна подключённая библиотека (через `figma.teamLibrary.getAvailableLibraryVariableCollectionsAsync()`); каждый вызов в `try/catch`, ошибка коллекции → пропуск, ошибка целиком → `libraries: []` и фолбэк к локальным флагам.
  - `buildSnapshot(selectedSource: SelectedSource)` — принимает **один** параметр выбранного источника:
    - при `type: 'library'` — `getVariablesInLibraryCollectionAsync(libraryKey)` → batch `importVariableByKeyAsync` × N с `figma.ui.postMessage({ type: 'ds-scan-progress', current, total })` каждые 20 импортов; задержка `await new Promise(r => setTimeout(r, 50))` между batch'ами;
    - при `type: 'local'` — текущая логика чтения локальных variables/styles без изменений;
    - **N — это переменные одной библиотеки**, не суммарно по всем (в этом ключевое упрощение vs multi-select).
  - `isSnapshotStale()` — учитывает смену `selectedSource` (если `selectedSource` отличается от того, по которому построен текущий snapshot — stale → rebuild) **И** count library variable collections (новая коллекция → stale → rebuild).
  - **Permission resilience:** если выбранная library недоступна на момент `getVariablesInLibraryCollectionAsync` (reject) — sandbox отправляет специальный ответ UI (`'selected-source-unavailable'` или через существующее сообщение об ошибке скана с полем `reason: 'library-permission-lost'`), переключает persisted `selectedSource` на `{ type: 'local' }`, выдаёт `figma.notify('Library "<name>" is unavailable, switched to Local')`, продолжает скан с локальными источниками. (Точное имя нового сообщения — на усмотрение @backend, согласовать с @ui-engineer; симметрия catch обязательна.)
  - **Если ни одной library не доступно при `discoverSources()`** — возвращается пустой `libraries: []`, UI делает radio «Connected» disabled (см. трек B).
- `@backend`: расширить `src/sandbox/scanner.ts` — `ScanAccumulator` дополнить `remoteStyleIds: Set<string>` для пассивного обнаружения library styles при walking (без сетевого вызова — только сбор `style.id` где `style.remote === true`). Это база для будущих v1.1 фич (без поведенческой нагрузки в v1.0).
- `@backend`: расширить `src/shared/types.ts`:
  - **Новый тип** `SelectedSource = { type: 'local' } | { type: 'library'; libraryKey: string }`.
  - `SnapshotSource` — оставить для метаданных snapshot, но **без** `enabled`-флага per-source (single-select не нуждается в коллекции включённых). Расширить `type: 'variables' | 'local-styles' | 'library-variables' | 'library-styles'`, добавить `libraryName?: string` и `libraryKey?: string` на library-вариантах.
  - `Token` — добавить `libraryName?: string` (optional, backward-compat). Оставлен ради опционального бейджа в UI и AI prompt; если PO откажется от бейджа (открытый вопрос #1) — поле остаётся для AI prompt.
  - **Новые `PluginMessage` (с симметрией ответа в catch):**
    - `'get-selected-source'` (UI → sandbox) ↔ `'selected-source-loaded'` `{ source: SelectedSource }` (sandbox → UI), включая catch-ветку с дефолтом `{ type: 'local' }`.
    - `'set-selected-source'` (UI → sandbox) `{ source: SelectedSource }` ↔ `'set-selected-source-done'` `{ success: boolean; error?: string }`, включая catch-ветку.
- `@backend`: новый файл `src/sandbox/sourcePreferences.ts` — `clientStorage` обёртка для одного ключа `'designlint-selected-source'`, экспортирует `getSelectedSource()` / `setSelectedSource(source)`. Хранит **одиночный объект**, не массив. По умолчанию (если ключа нет в clientStorage) — `{ type: 'library', libraryKey: <первая доступная> }` если есть библиотеки; иначе `{ type: 'local' }`.
- `@backend`: новые UI-строки в `src/shared/strings.ts` (English-only): `connectedLibraryLabel`, `localLibraryLabel`, `librarySelectedUnavailable` с placeholder `{name}`, `noConnectedLibrariesHint` (для disabled radio), ARIA-метки для radio и dropdown, опционально `libraryFromBadge` с placeholder `{libraryName}` (нужно только если PO подтвердит бейдж в ReportView). Названия ключей — на усмотрение @backend, согласовать с @ui-engineer перед использованием в UI.

**Критерий успеха:**
- `tsc --noEmit` — чисто.
- `npm run build:sandbox` — pass; размер `dist/code.js` Δ ≤ +2 KB (меньше прежнего лимита +3 KB благодаря отказу от multi-select preferences).
- На тестовом файле с выбранной библиотекой ~500 variables: скан завершается за 30–60 сек, UI получает `ds-scan-progress` событий ≥ 20 раз, не зависает.
- На тестовом файле с **отозванным доступом** к выбранной библиотеке: скан завершается без exception, видно `figma.notify` «Library "X" is unavailable, switched to Local», persisted `selectedSource` обновлён на `{ type: 'local' }`, скан продолжен на локальных.
- Старый snapshot без `libraryName` или построенный по multi-select модели — поднимается через `isSnapshotStale` → auto-rebuild при первом запуске после deploy.
- Симметрия `PluginMessage` для двух новых пар сообщений (`get-selected-source` ↔ `selected-source-loaded`, `set-selected-source` ↔ `set-selected-source-done`) и для сообщения о потере доступа подтверждена: try-ветка отвечает, catch-ветка отвечает, типы в `src/shared/types.ts` совпадают с фактическим `postMessage`.

**Среда:** Claude Code в терминале + Figma desktop (только Product Owner, для проверки на реальных файлах с library variables и сценария отзыва доступа).

**Исполнитель:** `@backend` → `@qa` (acceptance + регрессия Ф.16.5/Ф.16.6 + перфоманс на 500 variables + сценарий потери доступа).

## Трек B — UI (`@ui-engineer`)

### Шаг 16.6.5.B — Single-select раздел «Library content» на Home

**Цель:** Заменить текущий блок «Source of truth» на Home двумя radio (Connected library / Local library) с dropdown'ом подключённых библиотек под Connected, реактивным блоком «Source of truth» под выбором, и опциональным бейджем `from <library>` в карточке нарушения.

**Зачем:** Без UI-поверхности расширение из трека A невидимо: пользователь не знает, что библиотеки сканируются, и не может выбрать, какую использовать. Single-select модель PO 2026-05-09 переносит выбор с Settings (как было в multi-select) на Home — это ближе к тому моменту, когда пользователь думает «по чему я буду сканировать», и убирает целый раздел Settings.

**Действие:**
- `@ui-engineer`: переработать раздел «Library content» в `src/ui/components/Home.tsx`:
  - 2 radio через готовый компонент ДС (если в `components/ui/` есть `Radio` или `ListRadio` — использовать; если нет — точечно ввести `<Radio/>` через ДС с консультацией lead-architect; **не** создавать нативный `<input type="radio">` в продуктовом коде).
  - Под «Connected library» — `SelectField` (или новый `Dropdown` через ДС, если `SelectField` визуально не подходит к требованию dropdown списка библиотек) со списком библиотек, каждая запись — `name` библиотеки.
  - Реактивный блок «Source of truth» ниже:
    - при выборе Connected → показывает метрики выбранной библиотеки в формате «Variables — Color: N · Text: M» (числа из `tokenCount` либо разбивки по типам, если она есть в snapshot).
    - при выборе Local → показывает 2 radio «Styles» / «Variables» (сохранить текущее поведение, не менять).
  - **Permissions disabled state:** если sandbox вернул пустой `libraries: []` — radio «Connected library» **disabled** с подсказкой `noConnectedLibrariesHint` (например, «No connected libraries in this file»), default-выбор автоматически — Local.
  - **Library unavailable runtime:** при получении сообщения о потере доступа от sandbox (см. трек A) — UI обновляет состояние radio на Local + показывает inline-уведомление через готовый `Toast`/`ErrorCard` либо опирается на `figma.notify` от sandbox без дублирования (выбор делает @ui-engineer; принцип — без двух уведомлений на одно событие).
  - Подписан на сообщения `'selected-source-loaded'` и `'set-selected-source-done'`; отправляет `'get-selected-source'` при mount, `'set-selected-source'` при изменении radio/dropdown.
- **`src/ui/components/Settings.tsx` — НЕ ТРОГАТЬ.** Раздел Token sources не создаётся. Никаких правок в Settings в рамках этой фазы.
- `src/ui/components/ReportView.tsx` — бейдж `from <libraryName>` рядом с suggested token:
  - **Рекомендация архитектора: убрать бейдж в v1.0.** Обоснование: при single-select библиотека одна и явно выбрана на Home, бейдж дублирует уже известную пользователю информацию; UI становится чище. Если PO подтвердит — `@ui-engineer` пропускает эту правку, `Token.libraryName` остаётся в типах для AI prompt и v1.1.
  - **Если PO решит оставить бейдж** — реализовать через существующий `Tag` компонент с пропом `subtle` (или эквивалент). Если `Token.libraryName` не задан → бейдж не показывать (локальный токен).
- `@ui-engineer`: опциональная правка `src/ui/aiClient.ts` — учесть `libraryName` в AI prompt («this token comes from <library>»). Не блокер; если не успевается — отложить в v1.1 решением @ui-engineer.

**Критерий успеха:**
- `tsc --noEmit` — чисто.
- `npm run build` — pass; размер `dist/ui.js` Δ ≤ +3 KB (меньше прежнего лимита +5 KB благодаря отсутствию правок Settings).
- Скриншот Home с двумя radio и dropdown подключённых библиотек приложен; переключение radio меняет реактивный блок «Source of truth».
- Скриншот Home в состоянии «нет подключённых библиотек» — radio «Connected» disabled, активна Local — приложен.
- Round-trip persist: выбрать библиотеку, закрыть/открыть плагин — выбор сохранён.
- Сценарий потери доступа: выбранная library стала недоступна → UI переключился на Local, уведомление видно, persisted state обновлён.
- Скриншот ReportView соответствует решению PO по открытому вопросу #1 (с бейджем или без).
- Settings.tsx **не изменён** относительно Ф.16.6 (`git diff Settings.tsx` пуст).
- Использованы только готовые компоненты ДС — нет нативных `<input type="radio">`, `<button>` или собственных стилизованных примитивов.

**Среда:** Claude Code в терминале + Figma desktop (только Product Owner, визуальная проверка Home + ReportView).

**Исполнитель:** `@ui-engineer` → `@qa` (acceptance + регрессия Ф.16.5/Ф.16.6).

## Риски и митигации (обновлённые после single-select)

1. **🟢 Rate limit Figma teamLibrary API** — **менее критичен:** импортируем переменные одной выбранной библиотеки, не суммарно по всем подключённым. N снижен в k раз, где k — число библиотек в файле.
   *Митигация:* задержка 50 ms между batch'ами `importVariableByKeyAsync` остаётся. Exponential backoff — кандидат в v1.1, в v1.0 не реализуем.

2. **🔴 Permission resilience стал критичнее** — при потере доступа к **выбранной** библиотеке плагину больше некуда «упасть» (в multi-select можно было пропустить и продолжить с остальными).
   *Митигация (рекомендация):* fallback на `{ type: 'local' }` + одно `figma.notify` «Library X unavailable, switched to Local». Не требуем выбора от пользователя — это ломает flow. Persisted `selectedSource` обновляется автоматически. Альтернатива «требовать ручного выбора» отвергнута: блокирует UX, добавляет модальное окно.
   *Открытый вопрос PO #2 — ниже.*

3. **🟢 `clientStorage`** — хранится один объект `selectedSource` (≤200 байт), не список preferences. Лимит 1MB не релевантен.

4. **🔴 Backward compat snapshot** — старый snapshot мог быть построен из нескольких источников (multi-select prototype) или вовсе без library полей; новый — из одного источника.
   *Митигация:* `isSnapshotStale()` поднимает count и проверяет совместимость → auto-rebuild при первом запуске после deploy. Старые пользователи получают одну дополнительную задержку, не падение.

5. **🟢 Симметрия `PluginMessage`** — 2 пары новых сообщений (`get-selected-source` / `set-selected-source`) + 1 одностороннее уведомление о потере доступа от sandbox; симметрия catch обязательна, прецедент Ф.12.7.4.1 (`fix-violation` без ответа в catch) не должен повториться.
   *Митигация:* @qa проверяет симметрию явным баг-сценарием (отключённый clientStorage / эмуляция exception в `getVariablesInLibraryCollectionAsync`).

6. **🟡 Capability `teamLibrary` в `manifest.json` 2026.** Без изменений vs прошлой редакции — нужна сверка с docs.figma.com на 2026-05-09.
   *Митигация:* добавляем явно. Если в текущей версии Figma не требуется, добавление не ломает плагин и не блокирует submission. Не эскалирую.

## Открытые вопросы PO

При формулировании всплыли 4 вопроса. Не блокируют старт фазы (могут быть решены параллельно с треком A), но желательно зафиксировать до Ф.16.6.5.B:

1. **Бейдж `from <libraryName>` в ReportView — оставлять?**
   - (a) Оставить — напоминание, какая библиотека выбрана.
   - (b) Убрать — single-select на Home делает бейдж дублирующим.
   - Моя рекомендация: **(b) — убрать.** Упрощает UI, снимает одну правку с трека B. `Token.libraryName` остаётся в типах для AI prompt и v1.1, если PO передумает.

2. **Permission fallback — поведение при потере доступа к выбранной библиотеке.**
   - (a) Fallback на Local + одно `figma.notify` (рекомендую).
   - (b) Требовать выбор: показать модалку «Library X unavailable, please choose another or switch to Local».
   - Моя рекомендация: **(a) fallback на Local + notify.** Не ломает flow, persisted state обновляется автоматически, пользователь может выбрать другую library вручную в любой момент.

3. **Refresh library list на Home — явная кнопка или авто?**
   - (a) Явная кнопка `Refresh` рядом с dropdown.
   - (b) Авто-refresh при открытии плагина (один раз за сессию).
   - (c) И кнопка, и авто.
   - Моя рекомендация: **(b) авто-refresh.** Single-select упрощает UX — кнопка избыточна. Если в будущем (v1.1) пользователи будут просить «обновить без перезапуска плагина» — добавим явную кнопку.

4. **ADR-002 «Library styles listing limitation» — создаём сейчас?**
   - (a) Да, создать в этой фазе ради README_TESTER и явной фиксации ограничения для submission.
   - (b) Отложить до Ф.16.7 (чистка), создать вместе с release notes.
   - (c) Не создавать, ограничиться записью F-pre.1 в impact map.
   - Моя рекомендация: **(b) — отложить в Ф.16.7.** В Ф.16.6.5 фокус на реализации; ADR удобнее писать после прогона `@qa`, когда ограничения подтверждены на реальных файлах. Но если PO предпочитает (a) — задача S, делает `@release-scribe`.
