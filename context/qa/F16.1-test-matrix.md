# QA тест-матрица Ф.16.1 «Токены»

## Преамбула — Figma-специфика для прогона

- **Версия плагина:** v0.15.x (после Ф.16.1, до коммита). Уточнить через `package.json` → `version` перед стартом.
- **Среда:** Figma Desktop (macOS/Windows), `Plugins → Development → Import plugin from manifest…` → актуальный `manifest.json` из репо.
- **Скриншоты:** нативный DPR macOS / 1.0 zoom Figma; iframe плагина в дефолтном размере (440×720, заданном в `manifest.json`). Скрин — **только iframe плагина**, не весь Figma.
- **Эталон:** скриншоты `context/design/screenshots-2026-05-07/*.png` имеют ту же ширину 440px — сравнение «бок о бок» работает корректно.
- **AI:** ключ Gemini оставить настроенным (один кейс E2E проверяет AI-explanation).
- **Тестовые ДС:** один файл размера M (200–300 токенов) достаточен — Ф.16.1 не меняет сканер, S/M/L здесь не дают новой информации. Если есть готовый файл `dl-test-medium.fig` из прошлых прогонов — используй его.
- **Браузер DevTools:** `Plugins → Development → Open Console` — нужен для console-output по каждому кейсу (даже если «чисто» — фиксируй).

## Тест-матрица — 8 кейсов

### Кейс 1 — Home: containerPadding 26px

- **Где:** экран Home (= `ScanDesignSystem`), сразу после открытия плагина, до загрузки ДС.
- **Что сделать:** открыть плагин на пустом или любом тестовом файле; не нажимать ничего.
- **Что проверить:**
  - внешний padding контейнера = 26px (по 26px слева/справа/сверху/снизу от края iframe);
  - **визуально «больше воздуха» по краям** относительно прошлой версии (было 18px);
  - заголовок H1, подпись, кнопка «Got it» — не съехали, не обрезаны, нет горизонтального скролла.
- **Скриншот:** весь iframe плагина (440px ширина).
- **Эталон:** `01-home.png`.
- **PASS:** padding визуально совпадает с эталоном (26px), элементы выровнены как в эталоне, нет горизонтального скролла.
- **FAIL:** padding меньше/больше эталона; контент обрезан; появился скролл; элементы съехали.

### Кейс 2 — Ready-to-scan: ScopeSelector + Tags-категории читаемы

- **Где:** экран после загрузки ДС, статус `idle`, видны Scope-чипы и блок ДС с тегами категорий.
- **Что сделать:** открыть плагин на тестовом файле с подключённой ДС; дождаться парсинга ДС (Tags типа «Цвета 12», «Шрифты 4» появляются).
- **Что проверить:**
  - containerPadding 26px (как в кейсе 1);
  - **Tags-категории** (`<Tag>` компонент с `tagContent #FFFFFF`) — белый текст на тёмном фоне читаем; не должен выглядеть «грязно-белым» или серым;
  - Tag-цифры (счётчики токенов) видны полностью, не обрезаны;
  - чипы ScopeSelector выровнены, расстояния как в эталоне.
- **Скриншот:** весь iframe.
- **Эталон:** `02-ready-to-scan.png`.
- **PASS:** Tags читаемы, padding 26px, чипы на местах, текст в Tags не вылезает.
- **FAIL:** Tags выглядят серыми (не белыми); счётчики обрезаны; перекрытия чипов.

### Кейс 3 — ScopeSelector: caption→Body на чипах

- **Где:** тот же экран Ready-to-scan, фокус на ScopeSelector (4 чипа: Selection / Section / Top frames / Page).
- **Что сделать:** клик по каждому чипу поочерёдно (Selection → Section → Top frames → Page).
- **Что проверить:**
  - **текст внутри каждого чипа** (название scope, count selected) — был 13px, стал 16px;
  - текст **не выпадает за рамку чипа**, не переносится на вторую строку, не «срезается» по ширине;
  - active-состояние выделяется визуально (как в эталоне);
  - hover не ломает раскладку.
- **Скриншот:** весь iframe (можно поочередно с разными активными чипами).
- **Эталон:** `02-ready-to-scan.png` (active=Selection).
- **PASS:** все 4 чипа держат текст 16px без переноса/обрезания; active-чип явно выделен.
- **FAIL:** хотя бы в одном чипе текст переносится на 2 строки или обрезан; чипы переехали друг на друга; высота строки сломалась.

### Кейс 4 — ScanDesignSystem (Home): caption→Body, breakdown counts

- **Где:** экран Home в состоянии «ДС загружена», виден блок breakdown («Цвета: 12», «Шрифты: 4», «Эффекты: …», «Сетки: …»).
- **Что сделать:** открыть плагин на тестовом файле, дождаться парсинга ДС.
- **Что проверить (самый чувствительный экран — 16 ссылок мигрировали с caption на body):**
  - все подписи breakdown («Цвета: N», «Шрифты: N», и т.д.) — 16px (было 13px);
  - **счётчики «N»** не сливаются с подписью, отступы между ними как в эталоне;
  - блок breakdown **не выпал за пределы контейнера** по высоте — кнопка «Got it» / CTA внизу остаётся видимой без скролла (если в эталоне без скролла);
  - заголовки и meta-подписи — выровнены, плотность совпадает с эталоном.
- **Скриншот:** весь iframe; если контент уехал ниже видимой области — отдельный скрин со скроллом до низа.
- **Эталон:** `01-home.png`.
- **PASS:** плотность текста совпадает с эталоном (Body 16/20 везде); breakdown counts выглядят аккуратно; нижний CTA доступен.
- **FAIL:** счётчики переносятся; CTA уехал за iframe и появился скролл, которого нет в эталоне; визуально «слишком крупно» против эталона.

### Кейс 5 — ReviewFix card: caption→Body + Tag (tagContent)

- **Где:** экран ReviewFix card (= одна карточка нарушения), вход через Home → Scan → ReviewFix → клик по нарушению.
- **Что сделать:** запустить scan на тестовом файле; в Dashboard выбрать одно нарушение; открыть карточку.
- **Что проверить:**
  - **6 caption→Body миграций** в карточке: подпись «Файл», «Слой», «Текущее значение», «Рекомендация», meta-подписи под Preview — все 16px;
  - **Tag** (если виден в карточке — например, бейдж типа нарушения) — белый текст `#FFFFFF` (после `contentOnDark→tagContent`), читаем на тёмном фоне;
  - **dashed-preview блок** не сломан (это тот же inline preview, что был);
  - **AI-explanation блок** (если ключ настроен) — текст 16px, помещается в карточку без обрезания;
  - кнопки «Apply» / «Skip» / «Ignore» — на местах, не съехали, текст помещается.
- **Скриншот:** карточка closed (без AI explanation expanded) и opened (с AI explanation, если ключ есть) — два кадра.
- **Эталон:** `04-reportview-closed.png` и `05-reportview-open.png`.
- **PASS:** карточка визуально соответствует эталонам, Tag белый, текст не обрезан, кнопки доступны.
- **FAIL:** Tag выглядит серым; AI-explanation вылезает за карточку; кнопки съехали под низ iframe; текст карточки переносится так, как нет в эталоне.

### Кейс 6 — Settings: хардкоды fontSize 13/14 → 16

- **Где:** экран Settings (открывается через шестерёнку в Header).
- **Что сделать:** открыть Settings; ввести случайный API-ключ в Input; снять/поставить Checkbox «Enable AI»; нажать «Test API key» (можно с заведомо неверным ключом — баг-проверка не про API, про вёрстку).
- **Что проверить (3 хардкода в `Settings.tsx:113/116/142` мигрировали на body 16px):**
  - подписи полей (`Label` Input, описание Checkbox, About-блок) — 16px;
  - **раскладка не сломалась** — Input полной ширины, Checkbox с подписью на одной строке, About-блок снизу читается;
  - кнопка «Save» / «Test» работает (логика), не съехала;
  - **About-блок** показывает актуальную версию из `aboutVersion` (перепроверка — это критерий из Ф.16.1).
- **Скриншот:** весь экран Settings (если контент длиннее iframe — два скрина: верх и низ).
- **Эталон:** `09-settings-1.png` / `10-settings-2.png` / `11-settings-4.png` — **выбираешь тот, что фактически совпадает с реальным `Settings.tsx`** (контракт Ф.16.1 не определяет канонический — это вопрос #2 из impact map, ещё не закрыт). Скорее всего ближе всего `09-settings-1.png`.
- **PASS:** раскладка целая, все элементы видны и кликаются, About показывает текущую версию.
- **FAIL:** Input/Checkbox/About съехали относительно эталона; текст помещается криво; About показывает старую версию.

### Кейс 7 — Быстрая регрессия: Scan / Scan Error / Done

- **Где:** три экрана подряд во время полного цикла на тестовом файле.
- **Что сделать:**
  - (a) запустить Scan → пока крутится Spinner, сделать скрин (`07-scan.png`);
  - (b) **Scan Error:** запустить Scan на файле без подключённой ДС (или на пустой странице) → дождаться экрана ошибки (`ErrorCard`), скрин (`08-scan-error.png`);
  - (c) пройти весь цикл до Done (Fix all одним нажатием на тестовом файле с малым числом нарушений), скрин финального экрана (`06-done.png`).
- **Что проверить (поверхностно — не сломалась ли логика и визуал):**
  - Spinner крутится, заголовок «Scanning…» читаем (16px);
  - ErrorCard прижат к низу контейнера (acceptance Ф.14.2.10 — регрессия!);
  - Done показывает корректные счётчики «N fixed / N skipped / N ignored», CTA «Run again» работает.
- **Скриншот:** три кадра.
- **Эталон:** `07-scan.png`, `08-scan-error.png`, `06-done.png`.
- **PASS:** все три экрана визуально совпадают с эталоном; ErrorCard прижат вниз; счётчики корректны.
- **FAIL:** ErrorCard в середине экрана (регрессия Ф.14.2.10); Spinner не появляется (регрессия Ф.11.10); Done показывает неверные счётчики.

### Кейс 8 — E2E: полный цикл с AI

- **Где:** все экраны последовательно.
- **Что сделать:**
  1. Открыть плагин на тестовом файле с подключённой ДС.
  2. Перейти в Settings, ввести валидный Gemini API key, включить «Enable AI», сохранить.
  3. Вернуться на Home → Got it → выбрать Scope=Section → выделить секцию в Figma → Scan.
  4. Дождаться Dashboard (ReviewFix overview) → клик «Review one by one».
  5. На карточке одного нарушения — дождаться AI-explanation → нажать Fix.
  6. Дойти до Done.
  7. **Cmd+Z** после Fix (регрессия Ф.11.9!) — отмена должна откатить мутацию.
- **Что проверить:**
  - все переходы работают, кнопки кликаются;
  - AI-explanation отображается (текст 16px, помещается);
  - Cmd+Z откатывает Fix (нода возвращается к исходному значению);
  - в console — нет `error`, нет необработанных `warn` (любые `warn` — фиксируй в QA-отчёте).
- **Скриншот:** не обязательно полный цикл, но хотя бы (a) карточка с AI explanation, (b) Done в конце цикла, (c) состояние ноды до и после Cmd+Z (если возможно).
- **Эталон:** `05-reportview-open.png` (карточка с AI), `06-done.png` (Done).
- **PASS:** цикл проходится без падений; AI работает; Cmd+Z работает; console чисто.
- **FAIL:** на любом шаге плагин падает / зависает / показывает неожиданный экран; AI не отображается при включённом ключе; Cmd+Z не откатывает Fix; в console есть `error`.

## Что прислать обратно

Структурированный список по кейсам — формат как в QA-чеке v0.14.13 для трёх багов. Под каждый из 8 кейсов:

```
Кейс N — <название>: ✅ PASS / ⚠️ PASS-с-замечаниями / ❌ FAIL
- скриншот: <имя файла или вложение>
- console: <чисто / warn: ... / error: ...>
- комментарий: <краткое наблюдение, если есть>
```

Плюс отдельным блоком в конце:

```
Среда:
- plugin v<X.Y.Z>
- Figma Desktop <версия>
- macOS/Windows <версия>
- Тестовый файл: <имя>
- ДС-размер: S/M/L (<N токенов>)
- AI: on/off, ключ настроен/нет

Console output (полный, если есть аномалии): <вложение или вставка>
```

Если кейс упал в FAIL/PASS-с-замечаниями — приложи **дополнительный скриншот** с детализацией (например, кроп проблемного элемента) и явное описание расхождения с эталоном («подпись breakdown переносится на 2 строки на ширине 440px, в эталоне 1 строка»).
